### SourceScanner

![Syntax Structure](MermaidSyntaxView.svg)

The `SourceScanner` unit is the fourth software unit in the `Syntax` subsystem. It is three source files in the
`DemaConsulting.CanvasNet.Mermaid.Syntax` namespace: `SourceScanner.cs` defines the internal sealed class
`SourceScanner`, the delegate `ScanMatcher`, the record `ScanRule`, and the record struct `ScanToken`;
`SourceScanner.Patterns.cs` defines the grouped static class `ScanPatterns` (the matcher building blocks and the
JavaScript character classes); and `SourceScanner.Tokens.cs` defines the grouped sealed class `TokenCursor` (the
one-token lookahead of a parser).

#### Purpose

`SourceScanner` is the lexer infrastructure that the diagram parsers build on. Mermaid's parsers are generated by
jison from grammars without the `flex` option; their lexers take, at each position, the first rule of the active
start condition that matches (not the longest), keep a stack of start conditions, can return part of a match to the
input, and run an end-of-input rule once. The unit reproduces these semantics so that a parser port can copy the
rule and condition tables of a generated Mermaid parser and lex the same tokens, and it reports lexical and parse
errors as located `MermaidSyntaxException`s that list the expected tokens as jison's "Expecting ..., got ..." does.

The unit's behavior is specified by the `CanvasNetMermaid-Syntax-SourceScanner-*` requirements in
`docs/reqstream/canvas-net-mermaid/syntax/source-scanner.yaml`.

#### Data Model

- `ScanMatcher(string input, int position)` - a matcher anchored at a position: the length of its match (zero is a
  match of nothing) or a negative number when it does not match.
- `ScanRule(Name, Match, Action)` - a rule: the token kind it produces without an action, its matcher, and an
  optional action that may change the state, the token text (jison's `yytext`), or the position (`Less`), and returns
  the token kind or null to skip the match.
- `ScanToken(Kind, Text, Start, End)` - a token with its positions in the scanner input; `EndOfInput` (`EOF`) at the
  end.
- `SourceScanner` state - the input (a `MappedText`, so every position has a location in the original text), the
  rules, the condition table (the rule indexes of each start condition in the order they are tried; it must contain
  `INITIAL`), the stack of start conditions, the position, the current match, and jison's `done` flag.
- `TokenCursor` state - the scanner, the description of token kinds for messages, and the one lookahead token
  `Current`.

A scanner and a cursor lex one input on one thread; `ScanPatterns` is stateless.

#### Key Methods

- `SourceScanner.Next()` - lexes the next token: tries the rules of the active condition in order, consumes the
  first match, runs its action, and returns its token or continues after a skipped match. At the end of the input
  the rules run once more, so that an `<<EOF>>` rule (`ScanPatterns.EndOfInput`) produces its token once; after that
  every call returns `EndOfInput`.
- `Begin(state)`, `PopState()`, `TopState(depth)`, `State`, and `StateDepth` - jison's `begin`/`pushState`,
  `popState` (the initial condition is never popped), and `topState` (the initial condition beyond the depth of the
  stack).
- `Less(count)` - jison's `less`: keeps the first characters of the match and returns the rest to the input.
- `Locate(position)`, `LexicalError(position)`, and `Describe(text, position)` - the location of a position and the
  error for text that no rule matches, which describes the character found (a quoted character, a line break, a tab,
  a control character by its code point, or the end of the text).
- `TokenCursor.Current`, `Is(kinds)`, `Advance()`, and `Expect(kinds)` - one token of lookahead, lexed only when the
  previous one is consumed so that lexing stays in step with parsing (lexer states can change while a token is
  lexed); `Error(expectedKinds, hint)` builds the parse error, and `JoinAlternatives` joins the expected tokens as "a,
  b or c".
- `ScanPatterns.Literal`, `Run`, `Sequence`, `Choice`, `Optional`, `NotFollowedBy`, and `EndOfInput` - the matchers
  that replace the parts of the regular expressions of Mermaid's grammars, each linear in what it inspects;
  `IsJsWhitespace`, `IsJsLineTerminator`, and `IsJsWordChar` - JavaScript's `\s`, the characters that `.` does not
  match, and `\w`.

**Preconditions and postconditions**: the condition table must contain the initial condition and name only rules
that exist; a rule that matches nothing and produces no token must change the state. Every token's positions are
positions of the scanner input, which map to the original text.

#### Error Handling

- A null argument is an `ArgumentNullException`; a condition table without `INITIAL` or with a rule index that does
  not exist, and `Begin` with a condition that is not in the table, are `ArgumentException`s; `Less` with a count
  outside the match is an `ArgumentOutOfRangeException`.
- Text that no rule of the active condition matches is a `MermaidSyntaxException` with `mermaid-syntax-error`
  ("unrecognized text ...") located in the original text, with a hint to remove or quote the text.
- A token that the grammar does not accept is a `MermaidSyntaxException` with `mermaid-syntax-error` ("expected ...,
  found ..."), located at the token, whose `Expected` lists each expected token once in the grammar's own words.
- More than 1,024 consecutive skipped matches that consume nothing are an `InvalidOperationException`: a defect of a
  grammar port, never of the input, reported instead of looping forever.

#### Dependencies

- **Preprocessor** (same subsystem) - `MappedText`, for positions and locations
- **Root namespace** - `MermaidLocation`, `MermaidSyntaxException`, and `MermaidDiagnosticCodes`
- **.NET base class library** - collections, LINQ, and `System.Globalization`

#### Callers

`FlowchartParser` of the `Flowchart` subsystem builds its 122 rules and 21 start conditions on `SourceScanner` and
`ScanPatterns` and parses with a `TokenCursor`; `ScanPatterns`' JavaScript character classes are also used by
`Preprocessor`, `DiagramDetector`, `FlowchartModel`, `LabelBuilder` of the `Rendering` subsystem, and the color
parsers of the `Configuration` subsystem. The tests in
`test/DemaConsulting.CanvasNet.Mermaid.Tests/Syntax/SourceScannerTests.cs` drive a small grammar through the unit via
`InternalsVisibleTo`.

#### Known Differences From Mermaid

- **No regular expressions.** jison's lexers run JavaScript regular expressions; the ported rules are hand-written
  matchers with the same matches, so lexing is linear and cannot backtrack catastrophically.
- **Messages.** Lexical and parse errors carry CanvasNet messages, codes, locations in the original text, and hints
  instead of jison's "Lexical error on line ..." and "Parse error on line ..." texts; the expected tokens are listed
  as jison lists them.
