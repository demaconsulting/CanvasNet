### MindmapParser Unit Verification Design

This document describes the unit-level verification strategy for the `MindmapParser` unit in the
`DemaConsulting.CanvasNet.Mermaid.Mindmap` namespace: the internal sealed `MindmapParser` (the lexer and the grammar of
Mermaid's mindmap language and the calls of Mermaid's mindmap database, in two partial files), the token names
`MindmapTokens`, the node type `MindmapNodeType`, the node `MindmapNode`, the edge `MindmapEdge`, and the diagram
`MindmapDiagram` with the sections, classes, and edges of Mermaid's `getData`.

#### Verification Approach

The unit is verified in two ways. The upstream vectors (`Fixtures/upstream-vectors/mindmap-parser.json`, 246 cases
generated by `tools/visual-diff/mermaid/gen-diagram-vectors.mjs --type mindmap` from the pinned Mermaid release in
headless Chrome: the inputs of Mermaid's mindmap specs, each named in its `spec` field, original texts for every lexer
rule, bracket, string form, decoration, indentation, comment, and error path, and the 14 mindmap fixtures) give, for
each valid text, every node of Mermaid's database (id, node id, level, description, type, icon, class, section, root
flag, and children) and the nodes and edges of its `getData` (DOM id, label, label type, shape, classes, and the edge
ids, ends, and classes), and for each of the 42 invalid texts the first error Mermaid reports; a theory compares the
parser with every case. The unit tests then verify each rule, quirk, error, and limit on short texts, with the expected
values stated in the tests as literals.

No mocking or stubbing is used; the tests parse preprocessed texts with the real preprocessor and detector and call
`MindmapParser.Parse` directly through the test assembly's `InternalsVisibleTo` access. A vector case whose text is
not detected as a mindmap is compared as a failure of the detection.

Unit tests reside in `MindmapParserTests.cs` and `MindmapVectorTests.cs` within the
`DemaConsulting.CanvasNet.Mermaid.Tests` project, in the `Mindmap` folder.

#### Test Environment

- **Framework**: xUnit v3 running under the .NET SDK
- **Execution**: `dotnet test` invoked by `build.ps1` and the CI pipeline
- **Mocking**: None required
- **Fixtures**: `Fixtures/upstream-vectors/mindmap-parser.json`, copied to the output folder
- **Isolation**: Each test parses its own text; the vectors are only read

#### Acceptance Criteria

A unit-level test run passes when every scenario below passes without error or exception beyond those explicitly
asserted. Any node, level, parent, type, shape, text, decoration, section, class list, or edge that differs from
Mermaid's, and any error with another code, location, message, or expected-token list than asserted, constitutes a
failure.

#### Unit-Level Test Scenarios

##### CanvasNetMermaid-Mindmap-MindmapParser-Tokens: The Tokens Of Mermaid's Lexer

**Tests**: `MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`,
`MindmapVectorTests.MindmapParser_Vectors_FileHasEnoughCases_AtLeast200`,
`MindmapParserTests.MindmapParser_Parse_Tabs_CountOneEach`,
`MindmapParserTests.MindmapParser_Parse_TextAfterId_IsPartOfTheId`,
`MindmapParserTests.MindmapParser_Parse_Strings_KeepTheirText`,
`MindmapParserTests.MindmapParser_Parse_CommentsAndBlankLines_AreSkipped`,
`MindmapParserTests.MindmapParser_Parse_BlankLineThenUnindentedNode_FailsAsMermaidDoes`

Asserts that every vector case gives Mermaid's facts or Mermaid's first error, and that the file holds at least 200
cases, at least 35 of them from Mermaid's specs and between 30 and all but 150 of them errors; that a tab counts as one
character of indentation (a node indented by a tab is at level 1 and one indented by two spaces at level 2, its child);
that `root %% not a comment` and `a:::b` are node ids, the second without a class; that a quoted description keeps
`a [b] (c)`, a markdown string keeps `**bold**` without its quotes and backticks, and a description runs over a line
feed (`one`, a line feed, `two`); that a blank line, a comment line, and a line of spaces between nodes are skipped;
and that a blank line right after the keyword followed by a node at the start of a line fails at line 3, found
`NODE_ID`, with the expected tokens `SPACELINE`, `NL`, and `EOF`, as in Mermaid.

##### CanvasNetMermaid-Mindmap-MindmapParser-Shapes: The Shapes Of The Brackets

**Tests**: `MindmapParserTests.MindmapParser_Parse_Brackets_GiveMermaidsType`,
`MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`

Asserts (a theory with ten cases) that a node with the id `id` and no brackets is the default node (type 0,
`defaultMindmapNode`), `[text]` a rectangle (2, `rect`), `(text)` a rounded rectangle (1, `rounded`), `((text))` a
circle (3, `mindmapCircle`), `))text((` a bang (5, `bang`), `)text(` a cloud (4, `cloud`), `{{text}}` a hexagon (6,
`hexagon`), the mismatched `(text(` and `(text]` clouds, and `(-text-)` the default node, each keeping the id `id`.

##### CanvasNetMermaid-Mindmap-MindmapParser-Tree: The Tree Of The Indentation

**Tests**: `MindmapParserTests.MindmapParser_Parse_Indentation_BuildsTreeRelativeToRoot`,
`MindmapParserTests.MindmapParser_Parse_KeywordOnly_IsEmpty`,
`MindmapParserTests.MindmapParser_Parse_SecondRoot_FailsWithMermaidsMessage`,
`MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`

Asserts that the root indented by 4 and the nodes `a`, `b`, `c`, and `d` indented by 6, 10, 8, and 6 get the levels 0,
2, 6, 4, and 2, the parents none, `root`, `a`, `a`, and `root` (each the last node with a smaller level), and the depths
0, 1, 2, 2, and 1, with 5 nodes and 4 edges; that the keyword alone gives no root, no nodes, and no edges; and that a
second node at the root's level, `other[Other]`, fails at line 4, column 3, with Mermaid's message `There can be only
one root. No parent could be found for ("Other")` and no expected tokens.

##### CanvasNetMermaid-Mindmap-MindmapParser-Texts: The Ids And Texts Of The Nodes

**Tests**: `MindmapParserTests.MindmapParser_Parse_IdsAndDescriptions_AreKept`,
`MindmapParserTests.MindmapParser_Parse_Strings_KeepTheirText`,
`MindmapParserTests.MindmapParser_Parse_Texts_AreSanitized`,
`MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`

Asserts that `[The root]` takes its description `The root` as its id, that `child(The child)` keeps the id `child` and
the description `The child`, the string forms above, and that the description of
`root[<script>x</script>safe]` is sanitized to `safe` while its icon `<b>i</b>` is kept, as Mermaid's `sanitizeText`
gives them.

##### CanvasNetMermaid-Mindmap-MindmapParser-Decorations: Icons And Classes Of The Last Node

**Tests**: `MindmapParserTests.MindmapParser_Parse_Decorations_ApplyToLastNode`,
`MindmapParserTests.MindmapParser_Parse_DecorationBeforeNode_FailsLocated`

Asserts that `::icon(fa fa-book)` at the start of a line and an indented `:::urgent large` after the node `b` give `b`
the icon `fa fa-book`, located at line 5, column 8, and the class `urgent large`, so its class list is
`mindmap-node section-0 urgent large`, while the node before it has no icon; and that a class before any node fails
with `mermaid-syntax-error` at line 2, column 6, quoting Mermaid's JavaScript error
`Cannot set properties of undefined (setting 'class')`.

##### CanvasNetMermaid-Mindmap-MindmapParser-Sections: Sections, Classes, And Edges

**Tests**: `MindmapParserTests.MindmapParser_Parse_Sections_CycleThroughElevenAndInherit`,
`MindmapParserTests.MindmapParser_Parse_EdgeDepth_UsesIndentationLevel`,
`MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`

Asserts that with 13 children of the root and a grandchild under the last, the root has no section and the classes
`mindmap-node section-root section--1`, the children get the sections 0 to 10, 0, and 1, and the grandchild inherits 1
(`mindmap-node section-1`), with the last edge `edge_13_14` of the classes `edge section-edge-1 edge-depth-3`; and that
for a child indented by 4 and a grandchild by 8 the edges `edge_0_1` and `edge_1_2` have the depth classes
`edge-depth-1` and `edge-depth-5` (the parent's indentation level plus one, not the depth in the tree), as Mermaid's
`generateEdges` writes them.

##### CanvasNetMermaid-Mindmap-MindmapParser-Metadata: The Counts Of The Diagram

**Tests**: `MindmapParserTests.MindmapParser_Parse_Indentation_BuildsTreeRelativeToRoot`,
`MindmapParserTests.MindmapParser_Parse_KeywordOnly_IsEmpty`

Asserts that a mindmap of 5 nodes counts 5 nodes and 4 edges, and that the keyword alone counts no nodes and no edges.

##### CanvasNetMermaid-Mindmap-MindmapParser-Errors: Located Errors With Jison's Expected Tokens

**Tests**: `MindmapParserTests.MindmapParser_Parse_GrammarError_ListsJisonExpectedTokens`,
`MindmapParserTests.MindmapParser_Parse_LoneBrace_FailsLexically`,
`MindmapVectorTests.MindmapParser_Parse_UpstreamVector_MatchesMermaid`

Asserts (a theory with six cases) the token found and jison's expected tokens of each grammar error, with the code
`mermaid-syntax-error` and a hint: an icon on a node's line (found `ICON`, expected `SPACELINE`, `NL`, `EOF`); an
unclosed bracket (found the end of the text, expected `NODE_DEND`); empty brackets (found `NODE_DEND`, expected
`NODE_DESCR`); the keyword alone without a line feed (found `EOF`, expected `SPACELINE`, `SPACELIST`, `ICON`, `CLASS`,
`NODE_DSTART`, `NODE_ID`); a second `MINDMAP` keyword as a node (found `MINDMAP`, expected `SPACELINE`, `NL`, `EOF`,
`ICON`, `CLASS`, `NODE_DSTART`, `NODE_ID`); and `mindmap2` (found `NODE_ID`, expected `SPACELINE`, `MINDMAP`); and that
a lone `{` outside a description is unrecognized text at line 3, column 4.

##### CanvasNetMermaid-Mindmap-MindmapParser-Limits: Nodes, Depth, And Label Length

**Tests**: `MindmapParserTests.MindmapParser_Parse_TooManyNodes_FailsWithLimitExceeded`,
`MindmapParserTests.MindmapParser_Parse_TooDeep_FailsWithLimitExceeded`,
`MindmapParserTests.MindmapParser_Parse_LongText_FailsWithLimitExceeded`,
`MindmapParserTests.MindmapParser_Parse_LongClassList_FailsWithLimitExceeded`

Asserts that with `MaxNodes` 3 the fourth node fails with `mermaid-limit-exceeded` naming `MermaidLimits.MaxNodes` at
line 5; that with `MaxNestingDepth` 2 a node at depth 2 is accepted and one at depth 3 fails naming
`MermaidLimits.MaxNestingDepth` at line 5; that with `MaxLabelLength` 44 a text of 45 characters fails naming
`MermaidLimits.MaxLabelLength` as an id, a description in brackets, a quoted and a markdown string, an icon, and a class
(a theory with six cases); and that with the same limit the class `abcdefg` gives a class list of exactly 44 characters
and is accepted, while `abcdefgh` makes the class list too long and fails at the node's line 2, although the class
itself is short enough.
