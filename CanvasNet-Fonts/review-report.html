1. Introduction

1.1 Purpose

This document records the formal review of a set of project files.

1.2 Scope

This review covers the CanvasNet Fonts subsystem at the subsystem level only. The Fonts subsystem is entirely new this effort and comprises two units, TrueTypeFont and SystemFontCatalog, each of which has its own separate unit-level review-set (CanvasNet-Fonts-TrueTypeFont, CanvasNet-Fonts-SystemFontCatalog). Per the hierarchical-scope principle in software-items.md, unit-level implementation detail is excluded from this review; this review instead relies on the subsystem design document’s description of what the two units provide, and verifies that the subsystem’s own requirements, design, verification-design, bundled third-party asset documentation, and shared test infrastructure are internally correct, mutually consistent, and consistent with the surrounding system-level context.

Files under review (per .reviewmark.yaml review-set CanvasNet-Fonts):

  • docs/reqstream/canvas-net/fonts.yaml (subsystem requirements)
  • docs/design/canvas-net/fonts.md (subsystem design)
  • docs/verification/canvas-net/fonts.md (subsystem verification design)
  • test/DemaConsulting.CanvasNet.Tests/TestSupport/SyntheticFontBuilder.cs (shared test fixture helper)
  • src/DemaConsulting.CanvasNet/Fonts/BundledFonts/README.md (bundled third-party font licensing/provenance)

Context (not under review, used to understand intended role/scope only):

  • docs/design/canvas-net.md (system-level design)
  • docs/design/introduction.md (document conventions)
  • docs/reqstream/canvas-net.yaml (system-level requirements)

This is the first formal review ever conducted for this review-set in this repository; the reviews evidence branch contained no prior evidence to compare against or supersede.

3. Conclusion

3.1 Summary of Findings

# Check Finding
F1 DOC-03 (Pass — recorded for completeness given explicit review focus) Bundled font licensing/provenance is accurate. src/DemaConsulting.CanvasNet/Fonts/BundledFonts/README.md claims the bundled fonts are Liberation Fonts v2.1.5 (SIL OFL 1.1) plus Noto Project substitute fonts for Symbol/ZapfDingbats fallback (also SIL OFL 1.1). This was independently verified by inspecting the actual embedded .ttf binaries with fontTools (all 12 Liberation fonts report exactly Version 2.1.5 in their name table; the 3 Noto fonts report matching family names/versions) and by cross-checking DemaConsulting.CanvasNet.csproj’s EmbeddedResource/Pack entries, which embed and pack OFL.txt → licenses\LiberationFonts-OFL.txt and NotoFonts-OFL.txt → licenses\NotoFonts-OFL.txt exactly as the README describes. No inaccuracy found. Confidence: High (direct binary inspection plus .csproj cross-check). Low/informational note: the package’s top-level PackageLicenseExpression is MIT; this is a legitimate and OFL-compliant pattern (bundled OFL license texts are redistributed alongside the binaries), but a consumer who inspects only the NuGet package’s license expression — without opening the package contents or reading this README — would not learn that two sets of embedded binary assets carry a separate SIL OFL 1.1 license. Recommend (optional, not a compliance failure) a one-line pointer from the top-level repository README.md/package notes to this file.
F2 REQ-06, REQTEST-01, REQTEST-02, DOC-01, DOC-02 A cited test for TTC support does not exist. docs/verification/canvas-net/fonts.md’s Test Scenarios for CanvasNet-Fonts-TtcSupport name two tests as proof: TrueTypeFont_RealTtcContainer_FaceOne_RendersCffGlyphOutlineAsVisibleInk (exists, passes) and TrueTypeFont_RealTtcContainer_FaceZero_RendersGlyfGlyphOutlineAsVisibleInk (does not exist anywhere in test/ — confirmed by exhaustive grep across the whole test tree). The same phantom test name is also listed in the in-scope subsystem requirement CanvasNet-Fonts-TtcSupport (docs/reqstream/canvas-net/fonts.yaml) and in the out-of-scope unit requirement CanvasNet-Fonts-TrueTypeFont-LoadTtcExplicitFaceIndex. Fresh TRX results (generated same day against a clean git tree) confirm the trace matrix (dotnet reqstream --matrix) shows 0 passed/0 failed executions for this test name, and as a direct consequence dotnet reqstream --enforce (root-tags system,quality) reports CanvasNet-Lib-FontsTtcSupport, CanvasNet-Fonts-TtcSupport, and CanvasNet-Fonts-TrueTypeFont-LoadTtcExplicitFaceIndex as unsatisfied/unproven. This means the glyf-outline (non-CFF) rendering path for TTC face 0 has no actual automated proof despite being documented as verified. Confidence: High (directly verified via exhaustive grep of test/ plus reqstream trace-matrix evidence against a clean, same-day-built working tree).
F3 REQ-08 Four unit requirements are orphaned from the subsystem’s own decomposition. dotnet reqstream --enforce (root-tags system,quality) reports CanvasNet-Fonts-TrueTypeFont-CffSeacComposition, CanvasNet-Fonts-TrueTypeFont-CffCharsetResolution, CanvasNet-Fonts-TrueTypeFont-CffWidthResolution, and CanvasNet-Fonts-TrueTypeFont-LoadType1C as orphaned (unreachable from any root-tagged requirement). These exist as unit-level requirements (out-of-scope true-type-font.yaml) but the in-scope subsystem requirements file docs/reqstream/canvas-net/fonts.yaml does not list them in the children: of CanvasNet-Fonts-CffOutlineDecoding or CanvasNet-Fonts-Type1OutlineDecoding — i.e. the subsystem requirements file does not fully decompose/trace every capability the unit beneath it actually provides, per requirements-principles.md’s unidirectional-flow expectation that unit requirements trace up through their parent. Confidence: High (directly observed in both requirements files and in reqstream’s own orphan-detection output).
F4 REQDOC-02, DES-02 (context cross-check) Parent (context) system-level design doc is stale relative to the subsystem doc under review. docs/design/canvas-net.md (context, not itself under review) describes the Fonts subsystem’s “External Interfaces” and dependency list as if TrueTypeFont were its only public unit and Geometry its only dependency. It contains zero mentions of SystemFontCatalog anywhere (confirmed by grep), even though the in-scope docs/design/canvas-net/fonts.md explicitly documents SystemFontCatalog as “the second public unit of the subsystem, added this phase,” with its own public API (Fonts, FindBestMatch, LoadBundledFallback) and its own dependencies (RuntimeInformation, embedded BundledFonts). The in-scope requirements (docs/reqstream/canvas-net.yaml → CanvasNet-Fonts-SystemFontDiscovery) correctly trace down to the new unit, so only the parent design document is out of sync — it was not updated when SystemFontCatalog was added this phase. Because canvas-net.md is context rather than a file under review in this review-set, this is reported as an informational/process finding (not a Fail against a specific in-scope checklist row) but it should be corrected because it is read by this subsystem’s own stakeholders as its authoritative parent description. Confidence: High (directly verified by grep: zero occurrences of “SystemFontCatalog” in docs/design/canvas-net.md).
F5 (Process/tooling, informational) .reviewmark.yaml’s needs-review glob patterns silently exclude BundledFonts/README.md from automated elaboration/enforcement, despite it being explicitly listed in this review-set’s (and CanvasNet-Fonts-SystemFontCatalog’s) paths:. The root needs-review patterns match README.md only at the repository root, **/*.cs, and various docs/**/*.md/.yaml patterns — none match an arbitrary non-root README.md under src/. Consequently dotnet reviewmark --elaborate CanvasNet-Fonts lists only 4 files (omitting the README), and dotnet reviewmark --plan --enforce does not fingerprint or track this file as part of any review-set’s compliance evidence, even though it was explicitly singled out in this review’s commissioning instructions as a point of particular licensing concern. dotnet reviewmark --lint does not flag this gap. The same glob gap also silently drops src/DemaConsulting.CanvasNet/DemaConsulting.CanvasNet.csproj from CanvasNet-Fonts-SystemFontCatalog’s elaborated file list for the identical reason. This was reviewed manually per the task’s explicit instruction (see Finding F1), but the automated tooling’s enforcement pipeline does not currently cover it. Recommendation: add a needs-review pattern covering non-root README.md files (and/or .csproj files) that are referenced by any review-set’s paths:. .reviewmark.yaml is a protected configuration file and was not modified by this review. Confidence: High (directly reproduced: elaborate output verified to list only 4 of the 5 configured files; pattern list inspected directly).
F6 (Informational, out of scope) A repository-wide dotnet reviewmark --plan --enforce run reports 8 globally uncovered files, three of which are in the Fonts area: src/DemaConsulting.CanvasNet/Fonts/CffStandardEncoding.cs, test/DemaConsulting.CanvasNet.Tests/Fonts/BundledNotoFontsTests.cs, and test/DemaConsulting.CanvasNet.Tests/Fonts/CffStandardEncodingTests.cs. These are unit-level files, correctly out of scope for this subsystem-level review per the hierarchical-scope principle; flagged here only for the orchestrator’s awareness, to be addressed (if appropriate) under the relevant unit-level review-sets or a .reviewmark.yaml coverage update.

3.2 Overall Outcome

Overall Outcome: Fail

The Fonts subsystem’s design, requirements, and verification documentation are substantially well-constructed (clear subsystem design following the repository’s established Purpose/Units/Dependencies/Callers convention, no spelling/lint issues, and — of particular note given this review’s explicit focus — fully accurate bundled third-party font licensing and provenance claims, empirically verified against the actual embedded binaries). The shared test-fixture helper SyntheticFontBuilder.cs is well-designed, well-documented, and trustworthy shared test infrastructure with no significant findings.

However, the review identifies two substantive, objectively-verified compliance gaps that must be resolved before this review-set can be approved:

  1. (F2) The verification design and subsystem requirements both cite a test (TrueTypeFont_RealTtcContainer_FaceZero_RendersGlyfGlyphOutlineAsVisibleInk) that does not exist, meaning the TTC-support requirement chain (CanvasNet-Lib-FontsTtcSupport → CanvasNet-Fonts-TtcSupport → CanvasNet-Fonts-TrueTypeFont-LoadTtcExplicitFaceIndex) is not actually proven satisfied as documented.
  2. (F3) The subsystem requirements file fails to decompose four unit-level CFF/Type1 capabilities into its children: lists, leaving them orphaned from the system/quality root tags.

Follow-up actions required before approval:

  • Either implement the missing TTC face-0 glyf-rendering test, or correct the verification design and requirements to cite only tests that actually exist (F2).
  • Add the four missing unit requirement IDs to the appropriate children: lists in docs/reqstream/canvas-net/fonts.yaml (F3).
  • Update docs/design/canvas-net.md (parent/system-level design) to document SystemFontCatalog as the Fonts subsystem’s second public unit (F4).
  • Consider adding a needs-review glob pattern so BundledFonts/README.md (and similarly-situated non-root README/.csproj files referenced by paths:) are not silently excluded from ReviewMark’s automated elaboration and enforcement (F5).

No corrections were made by this review; all findings are reported for the orchestrator to act on, per this review’s read-only audit mandate.
